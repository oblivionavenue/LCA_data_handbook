# 交互式数据清洗技术手册 · Interactive Data Handbook

> 一个**单文件、零依赖、可离线运行**的交互式技术手册与工作日志面板。
> 原型来自我在消费电子行业做产品碳足迹（PCF）数据工程实习时的知识沉淀需求；本仓库为**完全脱敏的演示版本**，公司名称、内部系统名、真实物料 / 供应商 / 化学品数据均已移除或替换为示意内容。


---

## 1. 这个项目解决什么问题

数据工程类岗位的操作知识有三个典型痛点：

| 痛点 | 现实表现 | 本项目的应对 |
| --- | --- | --- |
| **知识零散** | SOP、录屏、聊天记录、Word 文档散落在多个位置，新人无统一检索入口 | 把全部规则收敛进**一个 HTML 文件**，17 个章节 + 侧边导航 + 全文检索 |
| **规则仍在迭代** | 平台工具每次更新，纸质文档立刻过期，没人愿意维护 | **页内直接编辑**，改完即存；可一键导出成新的 HTML 版本继续分发 |
| **过程不可追溯** | 每天做了哪些改动、遇到什么异常、怎么解决的，靠记忆和零散聊天记录 | 内置 **Data Engineering 日志**，以产品为单位按日留痕，可导出 JSON / CSV |

设计原则是**「一个文件即一个产品」**：不需要服务器、不需要 npm install、不需要账号，双击即可打开；同时又具备编辑、检索、批注、结构化记录这些通常要靠 SaaS 才能实现的能力。

## 2. 功能一览

### 2.1 内容层

- **17 章结构化正文**：从角色目标、术语、端到端流程，到平台自动化逻辑（三条数据管道、七条共享质检、去重规则）、人工核对要点、QA 场景应对、配置器校验、Excel 公式库、常量速查、文件索引。
- **平台逻辑 / 人工逻辑 / 缺口** 三色标签体系：明确区分「工具会自动做什么」「必须人工判断什么」「工具与现实不符的地方」——这是文档最容易失真、也最值钱的一层信息。
- **决策树与对照表**：把「同名异 CAS / 同 CAS 异名」这类容易误判的规则写成判定树与四象限表，而不是散文。

### 2.2 交互层

| 功能 | 说明 |
| --- | --- |
| 🔍 **全文检索** | 输入 2 个字符以上即时过滤，只显示命中段落并高亮，自动展开命中的折叠块；`Cmd / Ctrl + K` 聚焦，`Esc` 清空 |
| 🧭 **侧边导航 + 滚动高亮** | 章节分组导航，滚动时自动跟随当前章节 |
| 📂 **折叠块 / 展开全部 / 折叠全部** | 长表格与列定义默认折叠，避免信息过载 |
| ✏️ **页内编辑（本次新增）** | 点「编辑内容」后正文任意章节变为可编辑；`Cmd / Ctrl + S` 或「保存改动」写入浏览器本地存储，刷新后依旧生效；支持「放弃修改」与「恢复出厂内容」 |
| 🗒️ **Data Engineering 日志（本次新增）** | 以产品为单位的每日操作流水，详见下一节 |
| 📝 **选中文本加批注** | 在正文中选中任意文字即可添加笔记，锚点高亮回溯；笔记可导出 / 导入 JSON |
| ⬇️ **导出 HTML** | 把当前的正文修改 + 全部日志**固化进一个新的 HTML 文件**，可直接提交回仓库、发给同事或存档 |
| 🖨️ **打印 / PDF** | 打印前自动展开所有折叠块与日志详情，可直接存成交接附件 |

### 2.3 Data Engineering 日志板块（第 18 章）

面向「每天收工前当日报写一条」的使用场景：

- **以产品为单位**：可新建 / 重命名 / 删除多个产品线（如不同机型的 Base 数据），各自独立留痕。
- **结构化字段**：日期、阶段（数据清洗 / Screening / FMD 上传 / BOM 上传 / Mapper 匹配 / QA 响应 / 配置器检查 / 交付）、未 ready 零件数、待 locate FMD 数、是否上传平台（未上传 / 部分 / 已上传）。
- **自由文本字段**：当日改动与 QA 细项调整、异常事件、解决办法与结论、后续待办——保证「具体异常怎么发生、怎么被解决」这类经验不会流失。
- **顶部指标卡**：自动显示最新的未 ready 数、待 locate FMD 数、平台上传状态、累计记录条数，并用迷你柱状图呈现未 ready 数量的收敛趋势。
- **表格倒序 + 详情展开 + 编辑 / 删除**：任何一天的操作都可回溯与修正。
- **导出 JSON / CSV、导入 JSON**：JSON 用于换设备迁移与合并，CSV（带 BOM 头，Excel 直接打开不乱码）用于汇报与二次分析。

## 3. 技术说明

- **纯静态单文件**：原生 HTML + CSS + ES5 级 JavaScript，无框架、无构建步骤、无外部请求；断网可用，可直接嵌入任何笔记工具或静态托管。
- **数据存储**：全部内容修改、日志与批注保存在浏览器 `localStorage`，**不向任何服务器发送数据**；跨设备通过 JSON 导出 / 导入或「导出 HTML」完成迁移。
- **可维护性设计**：正文按 `<section id>` 分区存储，编辑覆盖以「章节」为最小单位，即使原始文件后续更新，未被编辑的章节仍会跟随文件版本；导出的 HTML 会把当前状态写进一个 `<script type="application/json">` 种子块，实现「文件即数据库」。
- **健壮性细节**：编辑模式下自动暂停检索、剥离批注高亮，避免把运行期 DOM 写进存档；检索时排除动态渲染的日志板块，避免过滤逻辑破坏表格状态；离开编辑模式前有未保存提醒。
- **兼容性**：Chrome / Edge / Safari / Firefox 现代版本。

```
<repo>/
├── data_engineer_handbook.html   # 手册本体（单文件即完整应用）
└── README.md    # 本说明
```

## 4. 使用建议

- **首次使用**：先浏览「00 · 面板导读」，了解平台逻辑 / 人工逻辑 / 缺口三类标签的含义。
- **日常记录**：每天收工前打开第 18 章，选择当前产品，填写当日条目；每周导出一次 CSV 作为汇报素材。
- **内容更新**：规则变化时点「编辑内容」直接改写对应章节，改完点「导出 HTML」把新版本提交回仓库，保持单一可信来源。
