01核心目标与全局图

🎯
核心目标
  1. 把 ODM 给的原始 BOM + FMD，处理成 LCA 平台 能识别的格式并上传;
  2. 建立正确的 Base BOM 结构，并使 FMD 与 BOM 的 component 建立正确的链接；
  3. 在 QA 阶段响应不同的模型 Update 需求；
  4. Configurator 检查，确保算出的 PCF / GWP 数字可信。

一台电脑的拆分

Base（主板总成）

以主板为核心的电子件总成，FMD 多由 ODM 提供。需要走完整的清洗 → 上传 FMD → 上传 BOM → Mapper → QA → Approve 流程。交接笔记与本面板主要覆盖这一块。

Chassis（外壳）

产品物理外壳结构件。单独建模，Configurator 里因材质不同会出现 Plastic、A Al + D xxx 等组合选项。

Shared Parts（共用件）

键盘、内存、SSD、电池、显示屏等多产品共用件，走独立的 Shared Parts / CSR 流程。

不是每个产品都要从头做一遍

打开 产品状态总看板，看 Base / Chassis 标的是 New 还是 Refresh——这决定工作量，也决定后面第 14 章「去哪里找正确的 GWP 参考值」。

标记含义要做什么
NewBase / Chassis 是全新设计必须走完整流程：新上传数据 → LCA 平台 建模 → QA → 得出全新 GWP
Refresh相比上一代改动不大，可沿用 / recycle直接引用上一代对应型号数据，或与 CS25 对应 config 交叉核对数字是否一致，无需重新上传建模

02概念与术语

按「文件 → 识别 → 结构 → 追踪」四组整理。

A. 两份核心文件

BOM · Bill of Materials 物料清单

记录一台产品由哪些零件、什么层级结构、各多少数量组成，是产品的「骨架」。每一行是一个零件，带 Level、名称、数量 Amount、MPN 等。

FMD · Full Material Declaration 完整材料申报

由零件供应商提供，逐一列明某个零件里含有哪些化学物质、各多少重量。用于 LCA 计算与合规（REACH、RoHS）。

B. 连接与识别

  • MPN — Manufacturer Part Number。每个零件唯一编号。LCA 平台 自动匹配靠相同的 MPN 把零件和它的 FMD 材料数据链接起来。MPN 对不上 → 材料数据挂不到零件上 → 计算出错或为空
  • RID — LCA 平台 里每个 model / 产品组的唯一地址，藏在 model 链接的 URL 里。手动匹配零件时用它精确定位。
  • Mapper — LCA 平台上的链接看板。BOM 上传后用它把每个 component 和对应 FMD / 数据集自动配对；没配上的以 unmatched 列出，需人工处理。

C. BOM 结构关键概念

  • Leaf 叶子件 — BOM 是树状层级，Leaf 是树的末端——真正的实体零件，需要 FMD 数据。Non-Leaf 是中间分组节点，也被称为 Trunk，只起层级作用、不能随便删。判断方法：看下一行的 Level 是否小于等于当前行的 Level，是则当前行为 Leaf。
  • Shared Parts — 多机型共用的标准件（通用螺丝、连接器、内存、SSD、电池、WiFi 模块等）。碳排已在 Shared Parts 流程单独算过，Base BOM 里标 Covered by Shared Parts 的行上传前必须删掉，否则 double counting。
  • BS/DS Part — 需要联想额外确认来源 / 处理方式的零件，往往没有现成 FMD，通常要找 Akiyama-san 确认。
  • BaseFill 80% Proxy — 某零件暂时拿不到 FMD 时用来「占位补齐」的近似模型，让该零件不至于完全缺数据。具体做法见第 13 章。

D. 计划与追踪文件

  • CSR / Master CSR — 分产品或汇总记录所有 Shared Parts 信息（含每个件的 url）的主表，也标注哪些 carbon relevant、哪些是 default 选项，是 Configurator 检查的对照基准。
  • Status Tracking — 产品状态总看板 — 记录每款产品时间线和各类文件是否就绪的总看板。
  • QA Tracker — QA Tracker（客户反馈表） — 按 base / chassis / shared_parts 分 tab，记录有问题的零件和反馈，随项目推进逐步更新。
  • Configurator — LCA 平台 面向使用者的产品配置界面，可按实际情况组合勾选配置，为每台不同配置的电脑计算 configuration-level 的 PCF。

04通用要求与输出结构 Appendix 2

要求细节
File format只能 .xlsx。从 .csv / .xls 或其他格式转换来的文件会丢失单元格颜色数据，而颜色是 OEM Part 检测的唯一依据
Max file size每个文件 50 MB。超过直接在解析前被拒
Encoding所有值都按字符串读入并去除首尾空白（trimmed of whitespace）
Sheet structure不能依赖宏、外部链接、数据行中的合并单元格
BOM + FMD pairing两个文件必须是同一个产品。除 MPN 匹配外没有任何交叉校验

05三条 Pipeline Appendix 2

选错 pipeline 或 sheet 名不对会直接 hard-fail。三条线的入口条件、必需列、以及缺列后果如下。

Pipeline适用FMD sheet 定位硬性前置
1 · ODM-AODM-A(Compal) Multi-Level BOM + GDXBomReport FMD必须恰好名为 Raw_Data，否则 hard-failFMD 第 1 行是标题行被忽略，第 2 行才是表头，数据从第 3 行开始

ODM-A 专属行为

  • Level increment：ODM-A 源 level 是 0 起算，pipeline 给每个 level +1，使顶层件成为 Level 1。
  • CAS apostrophe strip：ODM-A 常导出带前导单引号的 CAS（如 '7440-57-5），pipeline 在 CAS 校验前自动去掉。注意：其他两条 pipeline 未说明有此处理
  • Fuzzy PN match：精确匹配失败时，尝试去掉 FMD 料号末尾 2 个字符（如 12345678AB → 12345678）做二次匹配；成功则 Missing_MPN 记为匹配到的 FMD 料号而非 TRUE。

FMD 支持两种格式

格式检测方式关键差异
Standard（多件）第 1 行没有 Component Part Number 列物质列位于 component / material 行的下一行（T1 shift）；Material Name 字段编码为 CPN_MaterialName（T2 split）

Pipeline 3 · ODM-B — 双语表头与单位换算

BOM 过滤规则

  • 带字母后缀的 level（如 2A、3A）的行整行丢弃
    • （此规则原本是用于删除替代料，但后续发现仅替代料的Parent件标了A，其Leaf件没有标记，很容易误删。已与ODM沟通提供BOM前就删除所有替代料，因此后续产品可能不会出现该情况，但可提前检查一下）
  • Trunk 行（从 Level 1 开始的初始连续下降）永远保留
  • Virtual PN 行（Remark 含 Virtul PN , ignore FMD）——若其下没有真实子件则丢弃；有真实子件则保留
  • Remark 含 BS/DS part 的行 → 赋 Action Investigate if this is a shared part

某PC OEM客户 PN 为可选列，存为 ODM_B_PN 二级引用，不用于 FMD 交叉引用；交叉引用用的是 Part Number（ODM-B 自己的料号，与 FMD 的 ODM_B P/N 对应）。

FMD 双语表头处理

列标题可能是中英文两行，pipeline 只取第一个换行符之前的英文部分，再 remap 到标准名：ODM_B P/N、Component name→Component Name、Material Name、Material Weight、Material Unit、Substance Name、CAS Number、Substance Weight、Substance Unit、RoHS Exemption Code。

格式与关键列

扁平格式——每行一个物质，ODM_B P/N 每行都有，不需要 forward-fill。

列必需说明 / 缺失后果
ODM_B P/N必需缺失则所有行无料号，与 BOM 交叉引用完全失败
Component Name必需（优先）用作 FMD_Cleaned 里人类可读的 Material Name；缺失则回退到 Material Name；两者都缺则所有物质无材料分组
Material Name回退用仅当 Component Name 缺失时使用
Material Weight · Material Unit可选按 Material Unit 换算成 mg：单位为 g 则 ×1000
Substance Weight · Substance Unit必需 / 可选单位为 g 则 ×1000；缺单位默认按 mg 处理
🔢
单位换算规则：Material 和 Substance Weight 都支持 g / mg。单位列内容为 g 则 ×1000；其他任何值（或缺失）都被当作 mg 不做换算。所以单位列写成 G、gram、kg 之类会导致数量级错误且不报错。

🔎
Unrecognised CAS 实际上抓到的几乎全是 -。定义上它指「任何不符合 NNNNNN-NN-N 的值」，但实测下供应商 FMD 里真正触发这条检查的绝大多数就是 CAS 列写了 - 的行，被统一转成 other。这种情况无伤大雅——反正两者都不是有效 CAS，不会丢失真实化学身份，也不会被 T8 合并。
🧭
只有 T7、T8 会真正改数据（合并行、求和重量）。其余 5 条都只是打标记，数据原样进 FMD_Cleaned——意味着 zero weight、金 / 硅超标、non-CAS ≥ 5% 仅为问题标注，我们不需做任何改动，遵循QA建议即可（其中金 / 硅超标可能会在QA阶段由Akiyama-san等反映）。

通用的 BOM filter 功能

FMD_Cleaned 只保留 Component Part Number 能匹配到 BOM 中 MPN 的；不在 BOM 里的 FMD 行被排除出 FMD_Cleaned，但在 FMD tab 里逐字保留。

07FMD 去重逻辑深解：T7 vs T8

判定决策树

① 两行物质是否在同一 Component + 同一 Material 组内？

否
不处理。跨 material 的相同 CAS 是正常的，不报错。 同一颗料在不同材料层里出现同一种物质，属正常建模，不要人工合并。
是
继续判定下面两条规则（两条独立判断，可同时命中）。

② 两行 substance 名称完全相同？

是
T7 触发：重量求和、删重复行、留第一行、substance_consolidated = TRUE

③ CAS 是有效格式（匹配 NNNNNN-NN-N）且两行 CAS 相同？

是
T8 触发：重量求和、删重复行、留第一行、cas_duplicate_consolidated = TRUE

④ 其余情况

兜底
CAS 是 other / NA / confidential 且名称也不同 → 两条都不触发，两行都保留。
满足条件 不满足 / 保留 兜底分支

四种组合的实际结果

情况CAS名称触发结果与解读
完全重复相同有效相同T7 + T8合并。最干净的一类。
同 CAS 异名相同有效不同仅 T8合并。如 Zn vs Zinc；Epoxy resin / resin / Bisphenol A-epichlorohydrin resin（同为 25068-38-6）。合并后保留第一行的名称。
同名异 CAS不同相同仅 T7合并。
占位符 + 异名都是 other / NA / confidential不同—都不触发，两行保留。这就是「占位符 CAS 不按 CAS 合并」的含义。

08重量推导与 BOM Action Appendix 2

Analysis 文件中的 Component Part Weight 是算出来的，不是读出来的

🧮
Component Part Weight (g) = 该 component 所有 Substance Weight (mg) 之和 ÷ 1000
它不从任何源列直接读取，并且是在 T7 / T8 合并之后计算的。写入 FMD_Cleaned 时稀疏写——只在每个 component 的第一行，后续行留空。
后果：若某 component 的所有物质重量为 0 或无法解析，则 Component Part Weight (g) = 0.000000。
✅
所以重量加总关系可以不用人工检查。
Material Weight (mg) 确实是原样透传、不校验的（ODM-B 线仅做单位换算），但它不参与任何计算（component 重量跳过 material 层直接加 substance），所以即使它与下属 substance 之和不符，也不会污染 PCF 结果。

三层重量的单位与关系

层级单位应满足的关系谁来保证
Substance Weightmgsource of truth，以供应商申报为准，不要改动人工核对
Material Weightmg名义上 = 该 material 下所有 substance 之和，但不参与计算原样透传，不影响结果
Component Part Weightg= 所有 substance 重量之和 ÷ 1000平台自动推导

11手动转稀疏格式 SOP 人工逻辑

适用于「实在需要手动操作」的场景，典型是 ODM-B 原始数据手动转换：删除多余列 → 调整重量单位 → 改为稀疏格式。下面是在 Excel 里快速批量转稀疏的辅助列法，以及它的唯一风险点。手动操作演示：🔒 Recap: Handover doc Friday, July 24 | Meeting | Microsoft Teams（内部链接已隐去）

操作步骤

C / D 列（Material 级字段）

  1. 构建辅助列 MPN_Material = A列 & C列
  2. 构建第二个辅助列 Material_Check，判断 MPN_Material 是否等于其上一行
  3. 筛选 TRUE → 全选 C / D 列对应内容 → Clear Content

A / B 列（Component 级字段）

  1. 构建 1 个辅助列 Component_Check，判断 A 列对应单元格是否等于其上一行
  2. 筛选 TRUE → 全选 A / B 列对应内容 → Clear Content
  • A / B 列的清空只以 Component PN（A 列）为判断依据，不要用重量列
# 实测文件中使用的三条辅助列公式（第 2 行起）
Component_Check = A2=A1
MPN_Material    = A2&"|"&C2 # （拼接时加分隔符，避免串接碰撞）
Material_Check  = J2=J1      # J 列即 MPN_Material 所在列

唯一的误删场景

✅
这种方法唯一会误删的情况是：同一 FMD 内存在两个相邻的 Material Name 完全一致。误删后会只剩第一个，其下属 substance 可能出现 duplicate。该风险实际发生概率很低，建议数据量小，方便粗略检查的情况下才使用手动转格式。

  2. Mapper 显示每个 component 通过 Part Number - MPN （先看Part Number，没有就继续看MPN） 匹配 FMD 的状态；没匹配上的列在 unmatched（取消勾选 “Only show non-matched items” 可看全部）

  6. 判断链接是否Ready for QA最重要的一步：核对unmatched items，与此时BOM_import中标记的comment进行交叉对比，是否有：1）在BOM里未标注存在问题，但依旧没有match的item；2）在BOM里存在问题，但在mapper里自动匹配了的item
    • 问题1)：大概率FMD上传失败或出现了其他问题，建议回溯寻找原因然后手动调整；
    • 问题2): 可能是匹配上了数据库里的历史FMD。最好保证所有part都和最新上传的FMD进行配对，因此建议取消配对，等待新FMD上传之后再匹配

L3 → 分组键（T7 / T8 的作用域）；分隔符不可省
=J3&"|"&K3

替代做法 复制对应列作为辅助列 → 命名为 xxx_filled → Filter → 只勾选 Blanks → 输入 = 后按 ↑ → Ctrl+Enter，一次性向下填充。

1 · 判断 CAS 是否为「有效 CAS」

它决定一行会不会被 T8 合并，也决定它会不会计入 non-CAS 质量池。

M3 → 返回：有效CAS / 占位符 / 可疑
=IF(OR(TRIM(F3)="", LOWER(TRIM(F3))="-", LOWER(TRIM(F3))="na",
      LOWER(TRIM(F3))="other", LOWER(TRIM(F3))="others",
      LOWER(TRIM(F3))="confidential"), "占位符",
  IF(AND(LEN(F3)-LEN(SUBSTITUTE(F3,"-",""))=2,
         ISNUMBER(VALUE(SUBSTITUTE(F3,"-","")))), "有效CAS", "可疑"))
🧭
「可疑」才是要看的那一类。它意味着这个值既不是合法 CAS、也不是已知占位符——典型就是被 Excel 误转成日期或序列号的 CAS。筛选 M 列 = 可疑 就能一次性把它们抓出来。而 占位符 里绝大多数就是 -，会被平台统一转成 other，无需处理。

2 · 预测 T7（名称重复）与 T8（有效 CAS 重复）

跟平台一致，严格限定在同一 Component + Material 组内（即辅助列 L）。跨 material 的相同 CAS 不会被合并，也不会报错。

N3 → T7：同组内相同 substance 名称的条数
=COUNTIFS($L:$L, L3, $E:$E, E3)

O3 → T8：同组内相同有效 CAS 的条数（占位符不参与）
=IF(M3<>"有效CAS", "", COUNTIFS($L:$L, L3, $F:$F, F3))

P3 → 结论：平台会怎么处理这一行
=IF(N3>1, "T7 将合并", IF(O3>1, "T8 将合并", ""))
💡
两个坑：① COUNTIFS 会把 * 与 ? 当通配符，物质名含这些符号时计数会偏大；② COUNTIFS 不区分大小写，而平台的 T7 按精确名称匹配。数据量大时最好还是用 screening tool。

3 · 重量复核 选做

Component 总重由 pipeline 在去重后自动推导，无需人工校验（第 8 章）。下面两条仅在你想自己确认供应商数据洁癖度时使用。

Q3 → 该 material 下 substance 实际之和（对比 D 列存储值）
=SUMIFS($G:$G, $L:$L, L3)

R3 → 该 component 总重（g），应等于 B 列首行值
=SUMIFS($G:$G, $J:$J, J3)/1000

4 · 还原被 Excel 误转成日期的 CAS

在辅助列里跑，然后选择性粘贴为值，并把目标列格式设为文本 @
=IF(ISNUMBER(F3), TEXT(F3,"yyyy")&"-"&TEXT(F3,"mm")&"-"&TEXT(F3,"d"), F3)
  • ISNUMBER 判断该单元格是否已被存成日期序列号；是则重建，否则原样保留。
  • "mm" 补零、"d" 不补零——对应 CAS 的「中间两位 + 校验位一位」结构，所以 9003-1-4 会还原为 9003-01-4。
  • 前提 若已经被「改为文本」压成序列号字符串（如 2594322），先把该列格式改回日期，再用此公式。

5 · 清理隐形字符与前导单引号

去 NBSP(160)、零宽空格(8203)、BOM(65279)、控制字符、首尾空白
=TRIM(CLEAN(SUBSTITUTE(SUBSTITUTE(SUBSTITUTE(
     F3, CHAR(160), " "), UNICHAR(8203), ""), UNICHAR(65279), "")))

去掉作为真实字符存在的前导单引号（ODM-A 常见）
=IF(LEFT(F3,1)="'", MID(F3, 2, 999), F3)

快速清点：全表有多少格子含 NBSP（应为 0）
=SUMPRODUCT(--ISNUMBER(FIND(CHAR(160), $A$3:$H$9999)))

注 Excel 单元格开头的单引号通常只是「文本前缀标记」，不计入 LEN，也不会被上传；只有当它真是字符时上面第二条才需要。先用 =LEN(F3) 确认。

6 · 手动转稀疏格式的辅助列 完整 SOP 见第 11 章

步骤一：C/D 列——判断 material 是否与上一行同组
=IF(A3&"|"&C3 = A2&"|"&C2, TRUE, FALSE)
筛选 TRUE → 选中对应的 C、D 单元格 → Clear Contents

步骤二：A/B 列——只看 Component PN（A 列），继不拿重量当键
=IF(A3 = A2, TRUE, FALSE)
筛选 TRUE → 选中对应的 A、B 单元格 → Clear Contents
⚠️
两个已验证的细节：① 拼接时必须加分隔符 "|"，否则 AB+C 与 A+BC 会被误判为同组；② 第二步只能以 A 列为键——示例机型B-3 实测中有 112 对相邻不同 component 恰好重量相同（如 0.00016 g），拿 B 列参与判断就会误删。
